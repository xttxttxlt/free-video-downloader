# 需求分析

> 项目：闪存视频 FlashSave —— 万能视频下载网站
> 状态：一期已完成并实测（B站 / 抖音）

## 1. 背景与目标

很多用户想把平台视频保存到本地，但平台要么不支持下载、要么限制多（不能批量、清晰度受限、有水印）。目标是做一个**随时随地、手机电脑都能用**的万能视频下载网站，快速从各平台下载视频，并以实用价值吸引付费。

产品定位取舍（人工确认）：
- 前端：**突出实用价值、吸引付费**，而非单纯华丽
- 后端：**需要，但先不引入数据库**，尽量轻量
- 下载能力：**站在开源巨人肩膀上**，直接用 yt-dlp，不自己承担解析风险

## 2. 功能需求

### 2.1 一期（已实现）
| 编号 | 需求 | 说明 | 验收 |
|---|---|---|---|
| F1 | 链接解析 | 贴链接出封面/标题/作者/时长/清晰度列表 | B站、抖音实测 |
| F2 | 视频下载 | 服务器代下载 + 实时进度 + 浏览器取回 | 1080P/720P/360P 实测 |
| F3 | 清晰度选择 | 多档分辨率 + 仅音频 MP3 | 实测 |
| F4 | 抖音无水印 | 免用户登录/cookie 的专用解析 | 无水印 MP4 实测 |
| F5 | 批量/合集 | 多行链接 ≤10；合集展示前 50 勾选下载 | B站合集实测 |

| F7 | 免费额度 | 每 IP 每日 N 次（默认 5），超额引导会员 | 429 + 提示实测 |

| F10 | 自动清理 | 临时文件 1 小时删除 | 清理线程 |

## 3. 非功能需求

| 类别 | 要求 | 落地 |
|---|---|---|
| 轻量 | 单进程、无数据库、依赖少 | FastAPI + 内存状态 + 临时目录 |
| 易用 | 不装软件、不注册、贴链接即用；文案一行口语化 | 大胶囊输入框 + 友好提示 |
| 移动 | 手机优先可用 | 响应式断点 768/480 |
| 性能 | 并发可控、进度实时 | semaphore=3；1s 轮询进度 |
| 安全 | 防注入/防 XSS/不碰用户登录态 | 协议白名单、列表参数、转义、抖音游客身份 |
| 隐私 | 不留存用户视频 | 文件 TTL 1h 自动删 |
| 成本 | 磁盘/带宽不被打爆 | 单文件上限 500M、并发 3 |
| 可维护 | 引擎升级不改业务代码 | 只依赖 yt-dlp 稳定接口 |

## 4. 技术约束

- **运行环境**：本地 Windows + Python 3.10.4；yt-dlp 最新版要求 Python 3.11+，故 Windows 用官方独立 `yt-dlp.exe` 绕开版本限制
- **ffmpeg 必需**：音视频合并、MP3 转换依赖 ffmpeg/ffprobe 二进制（非 Python 包）
- **网络约束**：YouTube 等海外平台国内直连不通，需海外服务器/代理；B站/抖音国内可用
- **平台风控**：需登录/已删除/风控视频不可下；抖音分享页接口可能改版，需维护
- **无数据库代价**：重启后额度/任务/统计清零（一期可接受）
- **版权合规**：仅个人学习备份，页面须有免责声明

## 5. 关键决策记录

1. **后端栈**：Python FastAPI（人工确认），子进程封装 yt-dlp CLI
2. **付费深度**：一期只做额度 + 价格展示页，真实支付放二期（人工确认）
3. **目标平台**：一期优先 B站 + 抖音（人工确认）
4. **抖音路线**：不让用户提供 cookie、不做扫码登录（会泄露用户登录态）、不做纯插件（不符合网站服务定位）；改为**服务端游客身份 + 分享页解析**专用模块（人工确认方向，实测验证）
5. **UI 风格**：仿 ai.codefather.cn/painting 的白底亮蓝轻 SaaS 风（浏览器实测提取配色）
